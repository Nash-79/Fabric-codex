# Active work claims

Two coding agents work this repo in parallel (Claude Code and Gemini). This file is how each
one announces what it is about to touch, so the other does not edit the same file concurrently.

## Protocol

1. `git fetch --all --prune`, then read this file on `origin/main`.
2. If a file you need is already claimed → **pick different work.** Do not "be careful".
3. Claim your files here FIRST — commit `chore(locks): claim <task>` and push, *before* writing
   any code. A claim that arrives with the PR is not a claim.
4. Do the work on your own branch: one task, one branch, one concern.
5. Delete your claim when the PR merges.

A push conflict on this file IS the collision signal — re-fetch and choose different work.
Also check `gh pr list --state open --json headRefName,files`: an open PR touching a file is a
lock regardless of what this file says.

A claim older than 24h with no branch activity may be reclaimed (human call, not an agent's).

## Why this exists

This repo has already shipped a broken working tree from an edit that added the new version of a
line **without removing the old one** — both survived, nothing flagged it. Two agents on one tree
multiplies that risk. When you change a line, delete the version you replaced.
